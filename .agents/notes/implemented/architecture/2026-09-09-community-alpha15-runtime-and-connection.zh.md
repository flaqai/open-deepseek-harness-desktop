# Agent Note: 社区 0.1.5-alpha.1 运行时与连接集成

Status: implemented

[English](2026-09-09-community-alpha15-runtime-and-connection.md) | 中文

## 问题

上游 `0.1.5-alpha.1` 将桌面载体与 Web 服务器分离，并把 Session 存储升级到 V3。社区桌面仍向 Electron 和本机浏览器提供同一个 `web` Profile。直接复制上游桌面应用会改变共享方式，并绕过社区恢复能力和安装包下载。未适配的独立 RPC 适配器还会读取 Connection 不再注入的服务，导致 `dsh-pocket` 加载失败。

## 决策

集成目标为 `dsh-v0.1.5-rc.2`，提交为 `fb2c4b9e698e30edb738bca4cf0618587db7d203`。外部 Harness 运行时使用 Node `24.17.0`；Electron 保持 `43.2.0`，pnpm 保持 `11.7.0`。macOS 安装包要求 `13.5`，与外部 Node 二进制的部署要求一致。更新外部运行时不改变 Electron 内嵌的 Node。

社区桌面保留回环 `dsh web` 启动器、共享 Profile、浏览器认证、自定义桌面桥接和 GitHub 安装包下载器。上游独立桌面的更新协调器和云发布脚本不作为社区发布入口。官方右侧 Sidebar 与 V3 迁移链继续由上游拥有。

独立 Connection RPC 注册在调用插件的 effect 中保留通道名。物理路由使用显式注入 `webServer` 的子上下文；因此 Web Profile 会同时向 Connection 注入 `webRuntime` 与 `webServer`，而消费者只需注入 `connection`。释放调用方会撤回路由和通道名。缺少 Web 载体时保留待挂载注册，而不是强制中立的 Connection 服务依赖 HTTP。现有认证与 Host/Origin 校验继续保护每条独立路由。

诊断 Profile 就绪只证明安装方拥有的恢复界面能够运行。它既不创建活动 Profile 的可启动快照，也不提交待确认的快照恢复。仅进入诊断模式的恢复操作走现有启动失败回滚流程。

会话迁移保留 V0 → V1 → V2 → V3，以及证据充分的失败空工具身份修复。V3 读取器校验具名的 `external-tools/resolved` 审计扩展，不泛化接纳未知事件。原始代文件不变，插件快照不能撤销会话格式迁移。

桌面托管的插件变更在活动 home 的事务目录中准备并验证候选状态，保持正在运行的 Profile 不变。同一修改 token 将所有权从 CLI 移交桌面；激活后保留完整的旧依赖目录，直到普通就绪信号确认提交。失败时还原依赖和受管元数据，不回退会话或用户设置。启动恢复先完成日志收敛，再检查 Profile。隔离中断演练使用同一套激活和恢复命令。

pnpm 的 Node 工作进程在执行软件包代码前登记 PID，并从生命周期脚本环境中移除租约能力。控制进程或工作进程任一个仍存活时都不回收锁。候选准备保留 registry、Git、归档和本地来源的原始 spec；越出候选范围的相对来源及 workspace 来源会明确失败。启动预装、手动内置安装、导入恢复、恢复模式卸载及运行时后代插件命令使用同一套候选激活。候选生成的 pnpm 定位符会迁回活动 Profile，但不改变 manifest spec 或完整性；内置归档和 seed 标记随依赖树一起激活。新可启动点会把前一代降级而非删除，因此变更前状态仍可恢复。

插件激活等到 Harness 实际启动后才开始计算 180 秒服务端预算。服务端发布 URL 后，另给两个渲染器就绪信号 60 秒等待时间。重复启动或 URL 信号不会延长任一窗口。因此，磁盘冷读取和插件加载不会在服务端存在前消耗 30 秒渲染器预算。超时回滚记录具体失败阶段，保留原依赖树，不提交未经就绪确认的 seed 标记。因启动安装预算或失败冷却而暂缓的插件会出现在诊断中并提供重试操作，启动日志也将准备结果与激活结果分开记录。

首次准备在创建 Profile 前持久化 `bundled-plugins/first-start.pending`。原生构建保留带校验清单的预设模板，包含依赖文件但排除 store 和用户数据。首次部署使用一个候选目录和只读 Doctor，不运行 pnpm 安装。安全点可以记录 Profile 原本不存在的状态；回滚删除新激活的受管状态。复制中断后，仅在指纹匹配且旧所有者已退出时续接，复用已校验文件并重新验证。明确构建拒绝或模板不适配时使用有界的本地归档批量安装；模板损坏则停止。不允许部分候选进入客户端。待完成文件仅在普通就绪、提交和释放租约后删除。复用 Profile 保持增量策略。文件部署进度经过 IPC 节流，中断临时文件不进入激活后的依赖树。最终安装包清单在复制和签名后校验。回归测试覆盖不存在的 Profile 回滚、路径迁移、中断、损坏、构建规则和完成回调顺序。

## 考虑过的替代方案

**用上游 desktop Profile 替换社区启动方式。** 拒绝，因为它会拆分插件状态并移除共享的本机浏览器界面。

**禁用手机插件或恢复无条件 Web 依赖。** 拒绝，因为显式可选载体注入同时保留消费者和上游与载体无关的服务。

**把任何就绪界面都视为活动 Profile 健康。** 拒绝，因为恢复界面就绪可能把刚刚失败的插件状态错误认证为健康。

**随外部 Node 一起升级 Electron。** 未采用：两者运行时独立，用户选择保留 Electron `43.2.0`。

## 后果

运行时、迁移和传输检查不代表未测试操作系统上的安装兼容性。Windows、Linux、macOS x64、签名安装包行为和线上兼容清单发布仍需独立验证或批准。未接入的上游独立桌面模块不进入社区应用及其复制的构建产物。

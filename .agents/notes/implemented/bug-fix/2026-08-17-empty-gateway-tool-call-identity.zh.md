# Agent Note: 在网关流式字段为空时保留工具身份

Status: implemented

[English](2026-08-17-empty-gateway-tool-call-identity.md) | 中文

## 问题

某些 OpenAI 兼容网关会在工具调用的首个流式帧中提供标识符和函数名，之后传输参数片段时却将这些字段发送为空字符串。将这些占位值当作替换值，会记录空工具名，并使工具运行时拒绝调用。

## 决策

DeepSeek Chat Completions 转换器只使用非空的 wire 值更新工具块的 id 与名称。后续空占位值会保留同一工具调用索引已组装的身份；流中从未提供身份时，仍保留现有的空值回退行为。

## 验证

转换器测试覆盖了一个 `bash` 工具调用：后续参数片段携带空 id 和名称占位值，并断言每个输出增量与完成块都保留 `call_bash` 和 `bash`。

## 考虑过的替代方案

**要求网关省略缺失字段。** 被拒绝，因为这种不规范但常见的空字符串约定可以在适配器边界完成规范化，无需改变工具运行时。

**只要后续字段为空就拒绝工具调用。** 被拒绝，因为首个帧可能已经建立了完整身份；拒绝会丢弃安全且可执行的请求。

## 后果

使用空占位值的网关不再在流式过程中丢失工具身份。首次可用的 id 或名称为空的工具调用，仍会在既有的下游校验点被判定无效。

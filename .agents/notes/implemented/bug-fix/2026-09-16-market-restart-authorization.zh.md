# Agent Note: 显式桌面插件事务授权

Status: implemented

[English](2026-09-16-market-restart-authorization.md) | 中文

## 问题

常驻 Harness 将桌面变更授权传给市场 CLI 子进程。子进程成功时只暂存候选，没有更新活动 Profile，随后轮询事务管理器激活候选，在市场完成结果检查前停止 Harness。缺少激活日志不能排除这条路径；将该退出归因于市场重启按钮缺乏证据。

## 决策

Supervisor 从常驻进程环境中移除一次性事务所有权、租约、批次和候选来源变量。桌面 prepare 和 resume 命令保留显式授权。市场命令保留普通 CLI 写锁和自动快照流程；变更成功必须发生在市场检查结果之前。第三方归档和重启控件不作修改。

自动重启每秒检查外部写入者，最多等待十五分钟。它拒绝不可读的所有权及桌面自身遗留租约，恢复死亡进程留下的事务，并要求日志结算完成。停止操作取消等待并使迟到结果失效；主动候选恢复不经过该等待。日志区分主动停止、候选激活、异常退出、等待写入者和恢复。

Supervisor 每次启动都提供新的重启所有者标记和编号轮次。CLI 在启动 Profile 前认领该轮次，阻止继承标记的同目录 Web 替代进程启动竞争服务。被委托的替代进程最多等待 45 秒，直到同一所有者的较新普通轮次就绪；所有者失败、主动停止、所有者退出或非法状态都会结束等待，且不会初始化 Profile。这样市场 helper 不会把委托后的立即退出误判为启动失败并绑定竞争恢复服务。所有者在私有目录中原子发布的内容只有 PID、轮次与生命周期阶段；记录不传递启动 token 或变更权限。状态写入失败会拒绝启动；停止操作仍先清理自身子进程，再报告状态写入失败。自动 port-zero 重启保留上一轮实际端口，使原浏览器 origin 和恢复检查保持有效；主动 stop/resume 则清空该选择，以支持维护和目录切换。其他目录、Profile 与独立 CLI 启动保留普通行为。

受管 Harness 根进程退出后，Supervisor 通过该轮次现有的有界 Job/scope/group 所有者终止残留成员，然后要求确认范围已空，才检查写入者或启动替代服务。detached helper 仍属于 Linux scope，因此若先等待它的委托替代进程看到新轮次就绪、再清理旧范围，就会形成死锁。清理失败会阻止替代启动并发布终态失败；停止操作取消准入。已逃逸的 helper 仍遵循 CLI 的所有者就绪委托契约。

## 考虑过的替代方案

**保留隐式暂存但推迟激活。** 市场在 CLI 成功后读取活动 Profile，因此未激活候选会在实际变更可见之前报告成功。

**禁用市场重启按钮或修改其源码。** 两者都不能解决事务授权继承问题。用户要求保留原版市场流程和未修改的归档。

## 影响

市场操作提供快照恢复，不具备桌面完整候选依赖回滚；本次没有改变桌面回滚策略。原版市场重启模块在修复前产生两个存活 HTTP 服务，修复后只有一个。在 macOS 隔离 Profile 中，未修改的 dshmarket 1.47.0 安装测试插件、从 1.0.0 更新到 2.0.0、卸载并检查结果，期间没有新增 Harness 启动轮次；调用原版重启接口后恰好新增一轮。另一次生产入口 Electron 启动验证了调用该接口前后的客户端和事件分发就绪日志、HTTP 200 及 Electron 持续存活。Windows 实机行为仍未验证.

# Agent Note：保持设置操作与插件导航可访问

Status: implemented

[English](2026-08-29-settings-native-open-and-navigation-overflow.md) | 中文

## 问题

设置文档操作使用原生路径打开器，而其 Windows 适配器通过裸命令名 `powershell.exe` 启动程序。Host 的 `PATH` 受限时，即使 Windows 和文件关联均可用，该按钮仍会失败。设置导航也没有受高度约束的滚动子项，因此超出面板高度的插件设置分类会被面板的 overflow 规则裁掉。较长的翻译后导航文本和 Agent 预设状态标签还会溢出固定单行导航项或卡片标题；部分设置页则依据整个浏览器宽度选择响应式布局，而不是依据更窄的实际内容列。

## 决策

原生 Windows 从 `SystemRoot` 解析系统自带 PowerShell 的绝对路径，并依次使用 `WINDIR` 与标准 Windows 目录作为回退。适配器继续使用无 shell 的 argv 执行；只有 WSL 互操作保留裸命令名，因为 Linux 进程无法直接寻址原生 Windows 文件系统路径。

设置标题栏在“打开配置文件”操作紧邻的左侧放置桌面端持有的日志目录操作。其窄权限 preload 调用只会创建并打开固定的桌面日志目录；渲染器无法读取或提供文件系统路径。

设置导航栏把标题保留在独立滚动区之外。导航栏和列表可以在受限高度的 flex 列中收缩，而每个插件贡献项可以增高并显示完整的本地化名称。滚动区会限制滚轮越界传播，并预留稳定的主题滚动条空间。设置遮罩依据自身渲染器视口确定尺寸。

Agent 预设卡片会在卡片内换行显示名称和状态标签，不会将相邻卡片挤开。多列内容依赖设置页可用宽度的分区使用具名 inline-size 容器，因此单列回退由实际设置内容列触发，而非整个浏览器视口。文本标识允许 flex 收缩，无边界的用户值或提供方值会在所属内容中换行。

经 portal 挂到 `body` 的共享 `Modal`、首次引导接管层、连接横幅、附件拖放遮罩和图片灯箱使用完整的渲染器视口。默认弹窗内容具有内部滚动区，多列设置向导的左右两侧也具备受限滚动。这些规则会确保矮窗口或高显示缩放下仍可触达操作控件。

## 考虑过的替代方案

**继续调用裸命令名 `powershell.exe`，并修复 Host 的 PATH。** 这样会让用户可见的文件操作继续依赖可变的进程环境组合；只要受限启动器再次遗漏 Windows 系统路径，问题就会复发。直接解析系统自带可执行文件，可以让原生适配器获得确定的依赖，同时不必扩大所有子进程的 PATH。

**让整个设置面板或导航栏滚动。** 滚动外层遮罩会带走标题和操作按钮，滚动整个导航栏也会带走导航标题。使用可收缩的独立列表滚动区，可以固定持久控件，只让数量不受限的插件贡献项滚动。

**保持所有导航名称单行显示并加宽导航栏。** 更宽的导航栏会永久压缩每个设置页，而且无法覆盖任意长度的插件贡献名称。可变行高能够保留完整文本，额外的垂直空间则由现有滚动区承载。

**继续用视口媒体查询调整设置卡片。** 弹窗导航栏会占用一部分视口，因此实际内容列过窄时，设置页仍可能停留在双列视口断点。容器查询会依据分区真正可使用的空间选择布局。

**为设置或其他 portal 增加自定义标题栏偏移。** 按 portal 添加偏移会在 Web 组件中重复桌面几何，而且无法约束第三方全视口内容。桌面宿主会为 Harness 提供原生内容视口，该视口已经排除窗口 chrome。

## 后果

打开设置文档不再依赖继承到的 Windows PATH 项；相邻的日志目录操作可以直接访问本机诊断文件，同时不会向 Web 内容开放任意路径。任意数量的插件设置分类都可通过鼠标、滚轮和键盘焦点访问，同时设置标题保持固定，翻译后的导航名称也无需通过省略号猜测。Agent 预设卡片、插件清单、外部工具、导入插件恢复和快照控件会在实际内容列中自适应重排。经 portal 渲染的配置弹窗无需桌面专用偏移，也会限制在可用的渲染器高度内。

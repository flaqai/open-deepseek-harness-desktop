# Agent Note: 桌面退出要求已观察进程静止

Status: implemented

[English](2026-09-08-desktop-process-quiescence.md) | 中文

## Problem

忽略宿主清理失败会让 Desktop 在清理失败后仍然退出。清理完成前预约重启可能在上一代子进程仍运行时创建另一个写入者。

## Decision

生命周期控制器只在清理成功后预约重启。失败时清除待退出状态、报告错误并恢复窗口，以便重试。清理所有者传播失败，不丢弃 `allSettled` 结果。

运行时的 `process-control` 入口复用平台进程检查器。桌面每两秒观察 Harness 后代。Harness 与一次性命令优先使用现有原生 Job／scope 启动器，不可用时采用其进程组或进程树回退。Runner 使用选定的 Node 可执行文件，而非 Electron。Windows 会同时隐藏私有 runner 及其通过管道通信的目标，后台 Profile 操作不会创建控制台窗口。Windows 回退只有在子进程创建时间不早于候选父进程时才接受父子关系，防止父 PID 陈旧并被复用后把更早启动的无关进程纳入。命令结束后始终终止并验证受管范围；未确认的句柄继续保留，以便退出时重试。父进程变化后仍保留已观察身份；清理依次使用 TERM 和 KILL，发送信号前验证身份。原生 owner 先证明自身范围为空，观察器再清扫剩余身份，避免观察器提前结束 runner、反而让原生 owner 无法报告停稳的竞态。

独立守护进程使用选定 Node 运行时和同一套 process-control 实现。Electron 只把不透明记录标识、标签、明确的根身份以及 PID／启动身份原子写入带版本的恢复日志。正常关闭在移除日志后通知守护进程退出；IPC 意外断开时，守护进程接管带身份围栏的日志并回收旧代次，再删除日志。Desktop 会在 Profile 检查前隔离无法读取的日志和缺少明确根身份的旧日志，只保留一份 `.rejected` 证据并继续启动；当前格式日志中的精确自有身份若仍无法停止，则继续安全失败。

包管理操作可取消，默认最长运行十分钟。关闭界面显示等待、正常停止、进程回收和 Profile 检查等真实阶段。正常清理等待十秒后进入强制终止，再用五秒完成最终确认。只要受管范围仍存活、观察器失败或修改锁仍存在，就阻止退出与重启。失败页提供日志和重新回收，不提供强制重启绕过入口。

可选常驻服务路径要求稳定插件名与版本、服务标识、用途和 Host 计算的启动指纹。首次调用只记录待确认请求，不启动进程。许可绑定当前 Profile 和精确声明。运行时身份保存在独立日志中，每两秒采样一次，且只在确认退出后清除。普通 Harness dispose 与 Desktop 身份恢复都会排除已经批准的常驻身份；撤销许可、卸载插件与切换数据目录会先停止它们。正常插件清单卸载和启动恢复页卸载都会在服务清理状态不确定时，于修改软件包之前安全失败。已有存活的恢复身份会阻止同一服务启动第二份，并要求插件通过稳定协议重新连接。Windows 的外层 Desktop Job 启用静默子进程脱离，使普通 subprocess 能进入自己的 Job，而已批准常驻服务能保留独立范围。生命周期许可不会增加任何能力。绕过标准接口的插件仍是任意受信任 Profile 代码，也不会获得常驻保障。

## Alternatives considered

进程名和命令行匹配不能证明归属。直接子进程退出不能证明后代已经退出。原父进程退出后 Windows 可能复用其 PID，因此单独的父 PID 字段也不能证明归属。轮询只是兼容回退，不能替代原生受管范围。

## Consequences

通用设置展示脱敏后的进程清单，包含生命周期、状态、运行时间和管理方式，只接受不透明停止标识。待确认常驻声明必须由用户明确批准；撤销已批准声明时，会先回收运行进程，再删除许可。PID、argv、cwd 与环境从不跨越渲染层 Bridge。

快速退出的观察根进程可能在身份登记前消失；这种不确定性会阻止清理，而不是授权一次猜测式 kill。旧代码若在第一次观察前就主动脱离，仍可能逃出进程表回退。实现绝不按进程名、端口或命令文本批量结束进程，也不宣称这是恶意插件沙箱。

生命周期、调用、观察器、守护、授权与界面测试覆盖清理失败重试、PID 复用、Windows 陈旧父 PID、重挂父进程、无法读取及旧版日志隔离、取消、超时、指纹变化、重复服务拒绝、常驻身份排除、脱敏和明确授权。macOS 宿主测试验证已观察 detached 子进程的回收与本地常驻服务样本。单元测试验证 Windows 外层 Job 的静默脱离标志与私有 runner 协议，但 Windows／Linux 原生常驻、安装包启动与原生崩溃仍是发布前必须实测的项目，不能从其他平台结果推断成功。

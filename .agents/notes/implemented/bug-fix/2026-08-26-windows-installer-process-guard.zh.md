# Agent Note: 将 Windows 安装器进程检测限定为桌面端自有可执行文件

Status: implemented

[English](2026-08-26-windows-installer-process-guard.md) | 中文

## 问题

Electron Builder 26.15.3 会把可执行路径以 NSIS 安装目录开头的每一个进程都视为正在运行的应用。DeepSeek Harness 在该目录下携带 Node、Harness 与插件可执行文件；用户也可能从文本前缀相同的路径运行安装器或无关程序。通用提示不会指出命中的进程，因此隐藏的运行时子进程或错误的前缀匹配，看起来就像一个无法找到、也无法关闭的 DeepSeek Harness 实例。

## 决策

桌面端 NSIS include 使用安装目录自有进程守卫替换通用检查。它只匹配精确的应用可执行文件和位于 `resources` 目录边界下的可执行文件，排除当前安装器 PID，并报告命中的 PID、名称与可执行路径。交互安装在清理前征得确认；静默安装执行相同的有界清理。守卫先请求带窗口的进程退出，再仅强制结束剩余匹配项；如果更高权限的进程仍然存在，则携带可操作详情安全停止安装。

全新目标目录既没有桌面端可执行文件，也没有已打包的 `resources`，因此不可能存在占用安装文件的旧进程。NSIS 会原生识别该状态并跳过 PowerShell 进程检查；只要目标中存在任一安装边界，已有安装与不完整安装仍会进入受保护的检查路径。

Windows 桌面端显式退出也会通过 `taskkill /T` 停止受监管 Harness 的进程树，只有超过有界等待时间后才使用 `/F`。关闭窗口到托盘仍表示应用正在运行，升级时会有意识别到该状态。

自定义安装器 include 的展开早于 Electron Builder 插入 MUI2 与 `MUI_LANGUAGE` 宏。因此自定义的中英文 `LangString` 直接使用稳定的 Windows LCID 2052 与 1033；如果在此处引用 `${LANG_SIMPCHINESE}` 或 `${LANG_ENGLISH}`，常量尚未定义，而 NSIS 会因警告按错误处理而终止构建。命令行选项页面的函数通过 Electron Builder 的 `customHeader` 钩子生成；该钩子位于 MUI2 和语言载入之后，因此 NSIS 展开 `MUI_HEADER_TEXT` 时宏已经可用。

卸载器会内嵌 PATH 管理和文件移除辅助脚本，并在 `customUnInit` 阶段把它们释放到 NSIS 插件目录。`customRemoveFiles` 钩子先完成可恢复的文件阶段，再移除记录的 CLI PATH 条目或明确选择的个人数据。PATH 清理不依赖已安装资源仍然可用；文件阶段失败时，不执行这些后续副作用。

即使已经没有桌面端进程，旧卸载器也可能因文件锁或不支持的源路径、回滚路径长度返回退出码 2。调用它之前，升级协调器使用支持扩展 Unicode 路径的句柄操作，把准确核验的卸载器以外的全部普通文件与空目录暂存到同卷扁平隔离区。这同时避开过长的源文件名和未知的旧版临时路径长度，并保留原始根目录供注册信息与快捷方式处理。只有旧卸载器实际返回零才提交移除；其他结果会恢复文件且不替换冲突项，并保守恢复旧 CLI 辅助脚本造成的准确自有改动。只有退出码 2 才最多执行十二次、每次间隔五秒的尝试，不强杀运行中的卸载器，也不把所有失败都说成文件占用。恢复失败会保留日志与原始文件；旧版元数据是否恢复仍未经独立核验。

## 曾考虑的替代方案

**只匹配 `DeepSeek Harness.exe`。** 这能避免误报，却会遗漏内置 Node 与原生插件进程；这些进程仍可能占用升级时需要替换的文件。

**保留目录前缀匹配，只改进提示。** 更好的文案不能阻止安装器或前缀相似路径中的无关进程阻塞安装或被错误结束。

**不经确认就强制结束所有匹配项。** 这可能中断正在运行的桌面端 `dsh` 命令。因此交互安装会先询问，而显式静默模式仍保持非交互行为。

**绕过旧卸载器并强制覆盖文件。** 未采用，因为旧的 JavaScript、原生模块或运行时文件可能残留在新版本旁边，形成任何一个发布版本都未曾产生的混合安装。

**只缩短已知的长文件名，或重命名整个安装根目录。** 选择性缩短无法覆盖未知的旧版回滚路径前缀与深层空目录。根目录重命名不能证明各个文件都未被锁定，还会改变旧版元数据清理使用的目录。逐项暂存保持该目录不变，并在提交前检测拒绝删除共享的文件句柄。

## 后果

安装器或无关程序位于名称前缀相似的目录时，不再阻止升级或被错误结束。真实的应用、内置 Node、Harness 与原生插件进程仍受到保护，不会在运行期间被原地替换。Windows 包验证现在会清理孤立的内置 Node，保持无关相邻进程存活，让已安装的可执行文件被占用超过原始清理窗口，验证锁释放后同目录原子升级能够完成，并确认升级后的 Harness 再次就绪。

Windows 安装器也能在不依赖 NSIS 宏声明顺序的前提下保留经过审核的简体中文与英文文案。Electron Builder 安装后的卸载器会在启动进程退出后继续通过临时自复制进程完成工作，因此原生包验证会等待安装目录、当前用户 PATH 条目与桌面 CLI 所有权标记全部达到最终移除状态。任一生命周期回归都会在安装器发布前被拦截。

长路径事务增加了同卷重命名与持久化日志开销；中断的事务需要明确恢复，不自动重放。可移植文件系统测试覆盖 259/260/261 字符名称、回滚冲突与日志保留；NSIS 编译检查覆盖两个内嵌辅助脚本。这些检查不能验证 Windows 句柄共享、ACL 行为或真实 alpha.2 升级。发布此实现前仍须完成原生 Windows 验收。

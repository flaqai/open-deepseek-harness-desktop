# Agent Note: 社区 alpha.2 集成采用官方手机 UI

Status: implemented

[English](2026-10-28-upstream-alpha22-integration.md) | 中文

## Problem

社区手机抽屉、视口和焦点补丁与官方触屏交互更新重叠。此前仅对齐祖先的合并，也使 Git 推断的合并基点不足以导入完整官方差异。

## Decision

源码集成固定目标 `dsh-v0.2.2-alpha.2`，以记录的真实功能基线进行显式三方协调。最终提交保留社区与官方双方父提交。[集成记录](../../../upstream-integration.json) 只随完成的内容集成推进。

手机布局、侧栏导航、输入焦点和共享触屏原语采用官方组合方式。社区设置、审批解释、桌面主题和文件预览通过各自扩展入口保留。官方语言字典优先；韩语与社区独有字典继续保留，已有 `pt-BR` 偏好解析到官方 `pt`。

社区桌面展示已安装 LiveShare 的实验能力信息，但不自动选择该 Bundle。共享使用用户明确配置的自建服务和官方身份存储；启用不创建分享。NAS 对已知 LiveShare 安装和选择在 Profile 修改前拒绝，Host 激活检查也拒绝手动挂载的条目。不透明来源的包只能在解析后识别，仍受激活检查和事务恢复保护。

[冲突台账](../../../upstream-integrations/0.2.2-alpha.2.json)记录 295 个冲突路径及双方重叠但自动合并的路径。本决策取代[已归档的社区手机方案](../../archived/feature/2026-09-15-mobile-responsive-shell.md)中的抽屉与视口机制。

## Alternatives considered

同时保留两套手机布局会导致视口和焦点管理冲突，因此不采用。整套替换社区桌面和 NAS 实现会丢失认证、恢复和更新保证，因此不采用。默认公共共享服务不属于部署模型。

## Consequences

开发版本和外部工具兼容记录跟随固定官方标签。Python 和 Office 保持社区部署策略与已审核的固定版本。历史持久化记录保持不可变；并行审核链通过显式合并确认汇合，不改写前序记录。

原生启动暴露了两个集成缺陷：补充翻译可能早于官方所有者占用字典，以及通用设置读取 `remoteAccess` 却未声明依赖。补充字典现有独立、受生命周期管理的回退层，主字典不受激活顺序影响而优先生效；通用设置补齐服务与客户端模块依赖。原生就绪检查明确拒绝恢复页，即便恢复页随后输出服务就绪消息。

开发检查不代表安装包验收。手机键盘、跨平台安装，以及针对已配置服务的真实 LiveShare 登录，都需要发布前的独立证据。本次集成不创建发行标签或发布安装包。

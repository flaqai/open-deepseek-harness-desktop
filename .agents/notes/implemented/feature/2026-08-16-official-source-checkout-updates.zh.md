# Agent Note: 官方源码工作树更新

Status: implemented

[English](2026-08-16-official-source-checkout-updates.md) | 中文

## Problem

桌面源码运行模式没有用于发现或应用官方仓库稳定 Harness 变更的产品入口。若从渲染器执行不受约束的 pull，会向 Web 内容授予命令执行能力、覆盖未完成工作，并在依赖安装失败时留下只更新了一部分的工作树或构建产物。

## Decision

Electron 宿主持有一个窄接口源码升级器。上游固定为 `https://github.com/deepseek-ai/deepseek-harness.git`；在官方项目发布独立稳定渠道之前，稳定分支固定为 `master`。preload 只暴露检查、按精确 40 位提交升级和重启操作。

检查操作把分支拉取到 `FETCH_HEAD`，但不移动当前分支。状态区分已是最新、可升级、工作树未提交、历史分叉、非源码工作树和检查失败。可升级状态要求工作树干净，并且当前提交能够严格快进到已拉取提交。已经包含官方提交的分叉视为最新；提交历史发生分叉时必须人工合并。

升级操作会再次拉取并验证预期提交，然后执行快进、锁文件安装和完整构建。安装与构建不会继承名称包含 `KEY`、`SECRET`、`TOKEN` 或 `PASSWORD` 的环境变量。准备失败时会重置到记录的原提交并重新准备；任一回退步骤失败都会保持可见。只有升级成功后，用户才能通过另一项显式操作重启应用。

渲染端不再在「通用设置」中注册官方源码更新卡片。窄接口 Electron 更新器仍由宿主持有，以保留开发兼容性，但普通产品设置与 Web 客户端都不再暴露更新控件。

## Alternatives considered

- **暴露通用 Electron 进程 bridge：**不采用，因为任何渲染器失陷都会获得任意命令执行与文件系统访问能力。
- **自动合并分叉分支：**不采用，因为冲突解决与下游定制修改需要针对仓库进行审查；一键升级器无法安全保留其意图。
- **通过 Git 更新安装包：**不采用，因为安装包需要签名制品、发布元数据、原子替换和平台回退，而不是可变开发工作树。
- **移动分支后安装且不提供回退：**不采用，因为依赖或构建失败会使所选版本无法使用。

## Consequences

宿主保留有界的官方快进机制且不会暴露通用原生 bridge，但用户改为通过仓库工作流同步源码，而不是从「设置」执行。本地修改与下游分叉仍会在源码发生变更前阻止操作。该能力明确不更新安装包。

# Agent Note: Desktop 跨重启保留有界诊断日志

Status: implemented

[English](2026-09-15-desktop-persistent-diagnostic-log.md) | 中文

## Problem

打开 Desktop 日志目录不能指出包含故障的具体文件。Harness 输出没有逐行时间与来源字段，Electron 主进程的控制台故障只留在启动终端。因此，虽然原有 Harness 文件本身采用追加模式，重启仍会让用户实际使用的诊断路径丢失重要上下文。

## Decision

Desktop 在平台日志目录中拥有一个固定的 `harness.log`。每个进程生命周期追加开始与结束记录，其中包含随机会话标识、版本、平台、架构、打包模式与 PID。Desktop 控制台输出以及受监管 Harness 的 stdout 和 stderr 统一追加到该文件，并带 ISO 时间、来源标签与级别。拆分的子进程输出块会缓冲到完整行，Harness 代次退出时会写入最后一行未终止文本。

日志写入持久存储前会移除常见 Authorization 头、URL 凭据字段、用户信息密码和环境变量形式的秘密值。单条记录最多 64 KiB。应用启动时，当前文件达到 8 MiB 会轮转为 `.1`，最多保留四个历史文件。轮转发生在写入者打开当前文件之前；日志或轮转失败只写入原控制台，不会终止正在诊断的操作。

设置页顶部操作会打开固定的当前日志，不再只打开所在目录。当前文件不存在时，既有回退行为会打开父日志目录。

## Alternatives considered

每次启动创建新文件便于查看单次启动，但会丢失触发重启的故障。无限追加可以保存历史，却会无上限占用磁盘。拆分 Electron 与 Harness 日志可以明确来源，但会让用户猜测哪个文件解释启动故障，并把同一事件序列拆到多个文件中。

## Consequences

用户重启后仍可从设置页顶部查看此前的启动上下文。轮转文件保留有界的近期历史，但该日志不是永久审计归档。Desktop 主模块初始化前的故障、存储突然丢失，以及无法进入 JavaScript 的原生崩溃仍可能需要操作系统崩溃报告。基于模式的脱敏可以减少常见凭据泄漏，但不能保证任意插件输出无需检查即可公开。

聚焦测试覆盖行切分、时间、脱敏、轮转、跨重启追加、受监管启动失败与设置操作。原生安装包行为仍由发布平台矩阵验证。

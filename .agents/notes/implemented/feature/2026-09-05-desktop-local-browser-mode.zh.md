# Agent Note: 桌面端本机浏览器模式

Status: implemented

[English](2026-09-05-desktop-local-browser-mode.md) | 中文

## 问题

桌面应用已经在回环地址托管完整 Web GUI，但用户只能通过 Electron 窗口访问这套确切 Profile。另行运行 `dsh web` 可能选择另一 Harness home 或创建第二个进程；如果通过通用渲染层 API 暴露现有服务器地址，还会同时暴露其中的启动凭据。

## 决策

Electron 为每个 Harness 启动代次持有一个本机浏览器交接。它只接受就绪输出产生的带认证 `http://127.0.0.1:<port>/` 根地址，在主进程中保留 URL，并且通过 preload 只暴露不含 URL 的状态与打开操作。系统浏览器使用现有启动令牌换取绑定 authority 的 Cookie，因此与桌面窗口共用 Profile、会话、插件和 Host 进程。Electron 还在独立的随机回环端口创建仅限当前启动代次的返回凭证。浏览器通过片段接收凭证并从可见地址删除，只能用它显示已有窗口；监听器要求请求携带 Harness 精确来源和凭证。

在 macOS 和 Windows 中，通用设置、文件菜单和托盘菜单都提供该交接。默认关闭的桌面偏好会为每个不同的就绪 URL 最多自动打开一次。系统浏览器成功打开且托盘可用时才隐藏 Electron 窗口；自动打开失败会恢复窗口。已经失效的旧代次即使延迟返回，也不能隐藏当前窗口或重新发布就绪状态。

## 考虑过的替代方案

**启动第二个 `dsh web` 进程：** 不采用，因为它的生命周期、随机端口、Profile 选择和插件变更可能与 Desktop 已经监管的进程产生分歧。

**向客户端代码返回已认证 URL：** 不采用，因为渲染层只需要打开操作，而 URL 含有进程启动凭据；返回地址会把 preload API 扩展为 URL 载体。

**让 Host 监听局域网：** 不采用，因为本功能只服务同一台电脑上的单个用户。当前连接使用回环 HTTP，并未提供局域网或公网监听所需的传输安全。

## 后果

浏览器与 Electron 视图无需复制 Harness 即可操作同一份实时状态。浏览器依赖桌面进程，完整退出后会断开连接。外部浏览器没有 preload bridge，因此仍不显示 Electron 专属控件，只会获得“返回客户端”。每次 Harness 重启都会改变两类凭证，所以自动模式会打开新的认证代次，而不会尝试恢复已经失效的页面。

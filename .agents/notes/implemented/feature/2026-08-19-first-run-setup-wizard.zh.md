# Agent Note: 首次使用设置向导

Status: implemented

[English](2026-08-19-first-run-setup-wizard.md) | 中文

## Problem

原有首次使用体验把内测声明与 DeepSeek 专用凭据表单拆成两个阻塞弹窗。它没有介绍预装的消息集成，无法总览剩余配置，而且重复实现了模型编辑界面，没有把用户带到之后仍会使用的设置页面。

## Decision

首次进入空 Hero 时，会通过 `settings.onboarding` 挂载一套版本化设置向导。选定布局是一张宽幅、安静、与设置风格一致的弹窗，左侧只显示三步进度：连接模型、连接消息、准备完成。任务总览包含两项：配置模型 API Key，以及通过预装的 `@xmanrui/dsh-im` 插件配置微信或飞书。

向导不拥有任何一套配置表单。任务会用结构化请求调用设置外壳，指定已有分区、可选的功能自有子页、当前进度步骤与完成回调。外壳在不显示普通设置导航的引导框架中渲染该分区。该框架会 portal 到 `document.body`，位于总览弹窗设为 inert 的应用根节点之外，因此其中控件是唯一可交互表面，不会把点击穿透到底层任务列表。因此模型继续使用原有编辑器，消息配置则打开已有 Plugins 分区并选中 `im`。返回总览不会改变任务状态；显式完成页面才调用回调并显示绿色完成状态。若共享 Models 快照中已经存在可用模型，模型任务会直接从完成状态开始。

每项任务都可以跳过，“跳过全部”会一次解决两项。两项都有结果后，全部完成会显示“配置成功”；只要存在跳过项则显示“已准备就绪”，并提示之后可回到设置补齐。“开始体验”是唯一会持久化完成状态的操作：回环部署写入升级后的 `ui-onboarding.welcomeNoticeVersion`，远程浏览器继续使用既有的进程内回退。各任务的完成状态在最终操作前只保留于本次向导中，因此中途离开不会记录宿主无法证明的配置结果。

总览右上角的工具区放置一枚紧凑语言菜单。它读取共享 Locale 快照，并通过 `LocaleRuntime.setLocale` 写入，而不是维护向导专用偏好。因此语言变化会经标准 locale seat 同步刷新向导及复用的设置分区，沿用现有 Host 持久化，而且不会破坏向导中的本地任务结果。

## Alternatives considered

- **保留两个顺序阻塞弹窗：**否决，因为用户无法看到配置范围，消息能力仍不易发现，一次性模型界面也会与设置页逐渐偏离。
- **在向导内重新绘制模型与 IM 表单：**否决，因为同一套设置会产生第二套校验、持久化、无障碍与插件生命周期表面。
- **打开普通设置弹窗并高亮已有导航：**否决，因为无关选项会干扰首次配置，而且返回进度的行为不明确。
- **立即持久化每项任务结果：**否决，因为当前“已完成”只是用户离开复用页面时的显式确认，并非 Models 与第三方 IM 配置共同提供的新宿主能力事实。

## Consequences

设置引导 owner contract 现在携带结构化分区请求，设置分区可以接收可选的首选子页。外壳只拥有可复用引导框架与底部操作；功能插件仍拥有自己的表单、事实与变更操作。Plugins 分区会遵循请求的标签页，同时不改变普通入口的默认行为。

聚焦组件测试固定了分区路由、IM 子页选择、完成回调、绿色完成状态、跳过全部、最终确认、已配置模型路径，以及语言选择器对共享 Locale 的写入。客户端 contract 类型检查与 GUI 单元测试覆盖组合后的 slot 变化。本工作区默认不运行 Playwright，因此浏览器 replay 不属于本次本地验证范围。

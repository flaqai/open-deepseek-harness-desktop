# Agent Note：外部工具下载进度仅用于观察

状态：已实现

[English](2026-09-14-external-tool-download-progress.md) | 中文

## 问题

桌面用户安装 Codex 或 Claude Code 时，在受控 Profile 修改完成前只能看到没有细分的忙碌按钮。仓库响应慢或发生重试时看起来像卡死，且只有失败后才能查看更多诊断信息。

## 决策

现有受控安装器仍是修改、重试、超时、隔离与失败判定的唯一拥有者。主 pnpm 步骤可将 NDJSON 写入 Host 在选定 DSH home 内创建的 `0600` 权限边车文件。Host 把该流解析为粗粒度阶段，只有 pnpm 确定已解析依赖总数后才提供百分比，保留容量受限且经过敏感信息清理的终端记录，并通过 Host 签发的安装 id 与不透明字节偏移提供增量读取。边车路径从不暴露给渲染层；操作结束，或下次启动发现文件过期时，Host 会删除它。

桌面插件修改会先安装到待激活的临时候选 DSH home。处于该阶段时，CLI 根据受保护的事务来源而不是临时候选 home 验证边车文件。只有当前选定 home 与来源严格满足 `plugin-transactions/<profile>/<uuid>/candidate` 关系，并且 Profile 一致时才接受来源；任意进度路径和无关来源仍会被拒绝。

「外部工具」页面在现有安装按钮内渲染所报告的状态，并通过独立的次级按钮打开记录。依赖解析确定总数后，下载进度使用已取得依赖数，安装进度使用 pnpm 的已导入依赖数；因此下载很快或大量命中缓存时，也不会在两个不定进度阶段之间直接跳过真实百分比。关闭记录不会取消安装，百分比暂时不变也不会产生新的失败判定。

安装成功不会自动激活新连接。完成后的卡片变为由用户决定的「重启以启用」操作，并通过权限受限的桌面重启 Bridge 执行；它不会再次运行安装器，也不会在用户点击前自行重启。

安装运行时，进度操作分为「暂停」和「停止」。子进程能力没有跨平台的挂起操作，因此暂停不会声称冻结一个仍存活的操作系统进程。两种操作都会终止该 Host 签发安装 id 对应的受管进程范围，并等待其完全退出。暂停会保留可继续的界面状态；继续会重新发起相同的受控请求，并让 pnpm 复用内容寻址缓存。停止会保留已取消状态，且不会自行恢复。渲染层只能提交不透明安装 id，不能提交 PID 或信号。

## 考虑过的替代方案

**为每个阶段设置固定权重。** 依赖解析与生命周期脚本没有真实且统一的耗时比例；加权进度看似精确，实际是编造。

**每次安装快照都返回完整记录。** 重复传输量会随安装增长，并让普通状态轮询耦合可能敏感的原始子进程输出。

## 后果

用户可以区分准备、依赖解析、下载、安装与验证，并在重试发生时查看记录；失败后仍保留原诊断。缓存命中的软件包也计为已取得依赖，已导入软件包数会让确定进度延续到安装阶段。Windows 重试会重置确定进度，不沿用旧尝试的百分比。进度观察是可选能力：私有边车文件创建失败时，安装本身仍可继续。是否激活始终由用户明确决定。

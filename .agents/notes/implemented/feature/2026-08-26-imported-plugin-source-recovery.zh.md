# Agent Note：导入插件来源检查与本地恢复

Status: implemented

[English](2026-08-26-imported-plugin-source-recovery.md) | 中文

## Problem

桌面独立数据导入会保留可迁移的插件声明，但用户选择前无法判断 npm 或 Git 来源是否仍然存在。本地、带凭据和无法识别的声明虽然会被正确阻止，原来源消失时却没有受控替换入口。复制官方 Profile 的 `node_modules` 会带入平台相关的可执行状态，也会重新制造独立 home 本来要避免的依赖身份冲突。

## 决策

**可用性属于临时状态，并采用保守分类。** 打开恢复界面后，客户端使用内置 pnpm 在一次性目录中同时最多解析三个来源，禁用生命周期脚本，并为每项设置十秒超时。解析成功表示可用；确认 registry 中不存在、版本不存在、仓库或 Git ref 不存在才表示不可用。超时、断网、鉴权、授权与限流均归为未知，因此临时服务故障不会被错误解释成插件不存在。与已安装或预装依赖匹配的条目继续显示为客户端已提供并跳过解析。这些状态与有界诊断只存在于 Electron 进程中，第一版恢复清单 schema 保持不变。

**在线选择由可用性约束。** 可在线恢复的普通插件默认选中；来源不可用的条目不能进入在线安装器；状态未知的条目默认不选，但用户可以明确选择后仍尝试联网恢复。本地路径、带凭据地址和无效声明不会被直接执行。外部工具包继续沿用原有的仅联网安装流程，不能用本地归档替换。

**本地恢复只接受重新验证的包。** 渲染层只提交不透明恢复 id，并请求 Electron 打开源码目录或 `.tgz` 选择器。源码目录必须声明完全一致的包名，并由内置 pnpm 通过包管理器配置项禁用生命周期脚本后重新打包。归档会复制到一次性目录，大小限制为 200 MiB；所有归档路径都要检查绝对路径与路径穿越，且只读取不超过 1 MiB 的常规文件 `package/package.json`。包名必须完全匹配。已知本地版本与原导入声明不同时，需要用户再次确认。

**安装继续复用标准插件管线。** 验证完成后，Electron 把临时归档交给 `dsh plugin --profile web add`，因此构建许可、依赖诊断和共享 Host 修复仍然生效。在线选中的插件会通过一次 CLI 批量命令安装到一个受管候选目录，全部完成后仅激活一次 Harness；任何插件或激活失败都会回滚整批，并将所选条目全部报告为失败。本地归档沿用同一候选路径。只有候选激活成功后才记录恢复成功，已经激活的恢复不会再次要求重启。成功、失败或取消后都会清理临时文件，用户选择的本地绝对路径不会写入恢复清单。安装失败会以有界诊断持久保留并允许重试。即使用户主动选择官方 `node_modules` 内某个包目录，也不会扫描、复制或接管旧的已安装内容，而是重新验证、打包并安装。

**源码模式提供仅存在于渲染层的失败模拟。** 只有 preload 暴露源码模式能力时，恢复界面才显示检查中、断网、超时、鉴权失败、限流和确认不存在等按钮。模拟状态从最新真实快照派生临时视图，不调用来源检查，也不修改恢复清单；恢复真实结果前，安装、本地来源、重新检查、关闭清单和重启等有副作用操作均保持禁用。安装版不会获得该能力。

**插件恢复拥有独立的桌面设置分区。** Electron 暴露受限恢复桥时，“插件恢复”才会作为左侧导航中的单独页面注册，位于“外部工具”和“诊断”之间；普通 `dsh web` 不会出现没有意义的桌面迁移入口。原有首次进入弹窗和“插件列表”内嵌卡片均被移除，因此导入用户数据后不会中断客户端进入，也不会把迁移任务混入实时插件清单。没有恢复清单时该页面仍显示明确空状态；存在清单时则持续展示已完成、失败和待处理的条目。

## Alternatives considered

- **复制旧的已安装包：** 否决，因为这会在没有重放包管理与供应链检查的情况下迁移可变且平台相关的可执行状态。
- **把所有解析失败都视为不可用：** 否决，因为网络、凭据和限流只是临时状态，不能证明来源不存在。
- **持久保存可用性：** 否决，因为结果会过期，而且可安全重算的数据不值得引入 schema 迁移。
- **最终切换为直接复用官方 home：** 否决；此流程保持为独立环境导入，不会静默改变隔离模型。

## 影响

- 大型恢复清单的来源检查可能耗时，但不会阻塞 Harness 启动。
- 用户可以从源码或归档恢复未发布插件，同时渲染层仍不获得任意文件系统能力。
- 本地包可以有意与原声明不同，但必须先经过明确警告。
- 关闭并重新打开恢复页可以重新执行安全检查，过期的网络结论不会成为持久状态。

聚焦测试覆盖来源分类、并发上限、未知与不可用状态的选择差异、包身份、归档路径安全、临时文件清理、本地版本确认、严格 TypeScript、Desktop 构建和恢复组件。

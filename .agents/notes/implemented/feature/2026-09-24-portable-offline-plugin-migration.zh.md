# Agent Note：指定目标平台的离线插件迁移

Status: implemented

[English](2026-09-24-portable-offline-plugin-migration.md) | 中文

## Problem

桌面端导入到独立环境时会保留来源 Profile 的插件清单，但不会携带已安装的包。目标电脑断网时无法在线恢复；直接复制 `node_modules` 则会带入可变的平台专属可执行状态和 pnpm 项目链接。只有插件归档也不够，因为传递依赖仍需联网解析。

## 决策

源电脑可以联网制作一个指定目标平台的 `.tgz` 迁移包。桌面端从所选来源 Profile 读取实际安装的包名和版本，以精确版本与完整性校验获取 registry 的原始归档，也可以采用源 home 内已经过验证的归档。准备所选包的 pnpm store 与元数据缓存时禁用生命周期脚本。自定义、带凭据、Git、缺失及外部工具来源会列为排除项，而不是静默改变其来源身份。迁移包只携带插件归档和依赖缓存，不包含来源 Profile、会话、凭据或正在使用的 `node_modules`。

用户选择目标电脑的操作系统系列、CPU 架构和精确系统 release。若源电脑三项均与目标相同，导出时就会离线演练解析；若不同，则标记为目标电脑必须演练。桌面端在安装前检查归档条目、哈希、包身份和精确目标信息。目标电脑先离线演练，再通过受管候选事务只安装导入恢复清单中仍待处理的插件。只有目标插件激活后才记录成功；失败会恢复之前的受管依赖与恢复状态。迁移包不会授权渲染层访问任意路径，也不会在目标电脑自动回退为联网安装。

配置数据仍通过现有的官方或社区配置导入流程迁移。选择页询问插件是联网恢复还是从所选迁移包恢复，并将迁移包单独暂存于新 home。直接复用社区配置不执行这种独立复制迁移。

## Alternatives considered

- **复制已安装依赖树：** 否决，因为平台原生包、可变文件和 pnpm 项目登记会绕过重新安装，并重现依赖身份问题。
- **只导出顶层插件归档：** 否决，因为目标电脑仍需联网获取传递依赖。
- **在目标电脑下载：** 保留为独立的联网导入选项，但不能满足目标电脑断网的要求。
- **假定同一包适用所有目标平台：** 否决，因为原生和可选依赖随系统、架构与版本变化；迁移包只对应一组精确目标信息。

## 影响

导出可能需要联网并生成较大的文件，但目标电脑可以不下载包就完成所选插件的校验与恢复。每种目标平台组合都需要单独的迁移包；归档仍可能在依赖演练、构建授权或插件激活阶段失败。被排除的来源需要用户单独处理，迁移包有效或配置成功导入都不保证原有插件全部恢复。

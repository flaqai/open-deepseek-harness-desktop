# Agent Note: 灵感拼贴配对皮肤

Status: implemented

[English](2026-08-17-inspiration-collage-paired-skin.md) | 中文

## Problem

配色皮肤与聊天背景拥有独立的状态、持久化和设置控件。这种分离会保护用户选择的插画，但围绕一张插画设计配色的精选皮肤需要选择两次，才能呈现预期的完整构图。

## Decision

`ui-theme` 提供浅色 `inspiration-collage` 配色和 `idea-collage` WebP 背景。该配色从插画的薄荷色、青色、天蓝色、珊瑚色和黄色中派生出满足可读性的语义状态色；背景采用 `focus-right` 布局，使低细节纸张区域位于 transcript（文本记录）下方，并让拼贴留在外侧边缘。

外观设置行将这一套皮肤标记为配套背景。点击其主题卡时，同一操作会先调用现有主题动作，再调用现有背景动作。ThemeRuntime 不感知该配对：Host 偏好采用、重连和以程序调用 `setTheme()` 都不会替换浏览器本地背景。用户之后可以选择其他背景；再次点击该皮肤卡则会恢复精选配对。

源插画已获准随项目再分发，仓库只提交优化后的 1672×941 WebP 资产。它绝不会进入 Host settings、会话事件、附件或模型请求。

## Alternatives considered

- **让每个配色强制拥有一个背景：** 否决，因为现有用户可以自由组合任意配色与插画，schema 层的耦合会抹除这项选择。
- **在 `ThemeRuntime.setTheme()` 内应用背景：** 否决，因为 Host 同步和重连采用也会到达运行时偏好，进而意外覆盖用户后来选择的浏览器本地背景。
- **让精选配对保持为两次无关联点击：** 否决，因为用户选择具名皮肤时不会呈现完整视觉设计。
- **把源 PNG 作为本地自定义上传：** 否决，因为该皮肤是内置产品选项，必须在桌面应用和浏览器应用中无需逐浏览器设置即可使用。

## Consequences

设置界面新增一个有意配对的操作，而配色和背景状态仍可独立编辑并各自持久化。内置 schema 增加一个配色 id 和一个背景 id，默认 Web 应用新增一个插画服务路径，可见集合包含十一种皮肤与八张内置背景。

聚焦的主题、背景、引导和设置行测试固定这些 id、浅色配色方案、语义颜色、布局元数据、持久化与双动作操作。装配后的设置快照和响应式浏览器检查固定可见卡片与插画处理。

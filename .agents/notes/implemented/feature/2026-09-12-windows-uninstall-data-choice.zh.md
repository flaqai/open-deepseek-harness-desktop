# Windows 卸载数据选择

Status: implemented

[English](2026-09-12-windows-uninstall-data-choice.md) | 中文

## 问题

过去卸载 Windows 应用时始终保留应用拥有的本地数据。这对升级和重装较安全，但用户无法通过向导释放这些空间，也无法丢弃在重装可执行文件后仍然存在的损坏状态。

## 决策

NSIS 辅助卸载向导现在会在卸载文件前提供一个默认不勾选的数据删除选项。界面列出对话历史、模型与凭据设置、插件、插件快照、日志、缓存和桌面偏好，说明删除可能释放空间或清除损坏状态，并要求再次确认破坏性操作。

只有 `%APPDATA%\open-deepseek-harness-desktop` 下由安装版应用拥有的条目可以被删除，清理会明确保留源码运行使用的 `development` 子目录。卸载器不会解析 `data-home-setup.json`、跟随活动 `DSH_HOME`，也不会删除直接复用的官方 `.dsh` 或其他外部自选目录。静默卸载和安装器发起的升级会跳过该页面并保留数据。

macOS 的废纸篓删除和 Linux 包管理器没有同等可靠的交互页面。这些平台继续保留数据，不增加无法取得相同明确确认的卸载后删除脚本。

## 结果

- 普通卸载、静默卸载和升级默认继续保持非破坏性。
- 用户无需手动查找路径，即可主动重置应用拥有的全部桌面状态。
- 直接复用的外部数据保持在删除边界之外。
- 卸载安装版后，源码开发版数据仍然保留。
- Windows 安装包流程必须编译并目视检查自定义卸载页面；如果以后要求 macOS 和 Linux 提供同等引导，需要另行设计应用内入口。

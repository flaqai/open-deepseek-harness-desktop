# Agent Note：可卸载的内置预设插件

状态：已实现

[English](2026-08-18-removable-bundled-plugin-market.md) | 中文

## 问题

桌面安装包应离线提供选定的 Web 插件，同时让每个插件保持为用户可卸载、后续可更新的普通 profile 依赖。面向特定产品的外部工具集成不应在用户没有明确操作时安装。若写入核心 Cordis bundle，启动会恢复已移除插件；若把所有内置归档装成 `file:` 依赖，更新工具又无法识别 registry 身份。

## 决策

Electron 资源携带七个具有 SHA-512 完整性信息的固定启动 tarball。打包前，pnpm 会从 npm 官方 registry 通过每个精确 registry 条目的 `latest` 稳定 dist-tag 解析版本，下载并校验返回的 tarball，然后原子替换整套快照。固定 Git 条目保留经过审核的提交与归档。GitHub 打包在前置任务中只解析一次快照，并把同一组文件交给所有平台任务。清单 schema 2 将每个条目标为 `startup`、`manual` 或 `diagnostic`，并保留解析后的精确 registry spec 或固定 Git spec，供界面展示和后续明确更新使用。Codex 与 Claude Code 继续作为仅联网安装的外部工具。

打包应用启动时按清单顺序处理全部七个启动条目，并始终把经过完整性校验的本地归档路径而不是 registry package spec 交给 pnpm。因此启动预装不会解析或下载插件 tarball 本身；普通传递依赖的解析与 store 复用仍由 Profile 包管理器负责。成功安装内置归档时，系统会写入带桌面所有权的 schema 3 持久种子标记；接管现有依赖时则记录外部所有权。后续安装包携带严格更高版本的预设时，启动会替换由桌面管理的旧归档。schema 2 标记只要仍有依赖，就会执行一次真实已安装版本和所有权检查，即使标记已经声称采用安装包版本；只有解析到的 registry 版本低于安装包版本时才允许替换。外部或自定义来源、相同或更高的已解析版本、快照版本保持和卸载墓碑都会保留；启动绝不降级插件。单个条目失败会写入诊断，但不会阻止其余启动条目继续播种。运行时准备会从同一快照把启动条目安装到一次性 profile；诊断条目只会校验完整性，不会在演练明确请求前执行可选生命周期代码。

Better Sidebar 改为启动条目，和其他预设一样在 Harness 启动前安装；原先进入主界面后自动出现的右下角浮层不再注册。精确白名单的延后任务、进度轮询、重试、固定日志和重启能力继续保留，供用户明确触发的导入插件恢复流程复用，但不会自行启动。Codex 与 Claude Code 仍仅由“外部工具”手动联网安装。渲染进程不会获得通用安装器：沙箱 preload 只转发清单中 manual 条目的精确 profile 与 package spec 组合，其余安装请求继续经过受保护的 Host Remote。同一目标最多只有一个活动包管理写入进程，轮询任务保留有界诊断。

每个标记都会在 profile 移除后保留，因此后续启动不会自动重装对应插件。Windows 安装包使用官方 Node 可执行文件和参数数组运行内置 `pnpm.mjs`，不经过 shell 插值。Host 提供精确包名移除能力；启动和手动条目仍都是普通依赖，可以通过标准 profile 插件管理器移除。

## 考虑过的替代方案

- **核心 Web bundle：** 拒绝，因为无法独立卸载。
- **缺失就重新预装：** 拒绝，因为会撤销用户卸载。
- **把 Better Sidebar 延后到可用主界面后：** 实现后否决，因为 shell 时序和包版本漂移可能导致自动任务没有出现，额外重启也让首次使用不够可预测。Better Sidebar 现在进入确定性的启动预设；仅联网的外部工具仍由用户触发。
- **让每个平台任务分别解析 `latest`：** 拒绝，因为矩阵构建期间若有新版本发布，不同平台安装包可能携带不同插件版本。
- **在安装后的应用启动时解析 `latest`：** 拒绝，因为首次启动必须保持离线且可复现。
- **启动时优先 registry、失败后回退归档：** 拒绝，因为即使 registry 请求只是尽力而为，预装仍会受到网络状态影响并增加启动耗时波动。
- **本地安装后重写 lockfile：** 拒绝，因为离线环境不保证 registry 元数据，手工修改 lockfile 也会绕过 pnpm 的解析契约。
- **插件自卸载：** 拒绝，因为插件无法可靠移除自身正在活动的软件包和 bundle。
- **Windows 系统 Node 与 pnpm：** 拒绝，因为安装包必须自包含。

## 影响

macOS、Windows 与 Linux 安装包携带同一套已经解析的七个已审核启动归档和六个诊断资源。打包需要访问 npm registry，但发布后应用内的预装不需要网络。本地打包命令默认刷新 registry 归档；设置 `DSH_BUNDLED_PLUGINS_REFRESH=0` 时，只校验前置任务已经解析的快照。Better Sidebar 会在 Harness 启动前消耗对应的 profile 安装时间；Codex 与 Claude Code 在用户请求前不消耗安装时间。测试覆盖稳定版本拒绝、归档完整性、原子快照替换、仅本地安装、所有权感知的接管与升级、降级与卸载抑制、任务单写入、阶段进度、有界诊断和渲染进程回退。已安装 Windows 烟雾测试要求七个启动依赖在上传前全部就绪，而仅联网外部工具在用户操作前必须保持未安装。

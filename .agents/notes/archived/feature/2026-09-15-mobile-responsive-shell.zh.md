# Agent Note：手机端响应式外壳

Status: implemented
Archived: 2026-10-28

[English](2026-09-15-mobile-responsive-shell.md) | 中文

## 问题

原有紧凑桌面侧栏在手机宽度下仍保留固定图标栏，压缩了会话区域；设置页、输入控件和右栏控件也可能在长语言文案下重叠或无法操作。

## 决策

在 680px 及以下，布局改用有宽度上限的覆盖式侧栏抽屉，并提供模态焦点限制、不可交互的背景内容和导航后自动关闭。手机抽屉使用独立临时状态，不复用用户保存的桌面侧栏宽度偏好。打开右栏时先关闭抽屉，右栏沿用已有全屏展示，但不显示宽度或模式切换控件。

设置页在手机上使用栏目列表与详情两层页面。会话内容使用动态视口高度、安全区域内边距和更小的横向留白；输入编辑字号至少为 16px，工具栏可换行，主要触控区域为 44px。较宽的消息内容在自身区域滚动，不会撑宽整个页面。

## 备选方案

- 在手机上保留 56px 紧凑图标栏。未采用，因为它会持续占用本就狭窄的会话宽度，也无法容纳清晰可读的导航名称。
- 原地压缩现有三栏网格。未采用，因为这会把手机导航与桌面保存宽度耦合，并让左右面板同时与会话区域争夺空间。
- 增加滑动打开手势。暂缓，因为横向手势容易与文字选择以及代码、表格和媒体的横向滚动冲突。

## 结果

- 导航关闭时，手机会话区域占满完整视口宽度。
- 键盘和辅助技术用户可以稳定地进入、遍历、关闭抽屉并返回原触发控件。
- 跨越 680/681px 与 1023/1024px 断点时，桌面宽度偏好不会丢失。
- 真实 iOS Safari 和 Android Chrome 仍属于平台验收项；自动测试在不运行浏览器回放的前提下覆盖响应式状态和 CSS 契约。

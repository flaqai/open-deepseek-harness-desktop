# 事故复盘（postmortem）0005：兼容网关的空分片抹除了工具调用身份

[English](0005-openai-compatible-gateway-empty-tool-identity.md) | 中文

状态：已解决

## 执行摘要

一个兼容 OpenAI Chat Completions 的网关在工具调用的首个流式分片中提供了 `id` 和 `name`，却在后续参数分片中为这两个字段发送空字符串。DeepSeek 适配器把空字符串当作更新，覆盖了已保留的身份信息，导致原本有效的 `bash` 调用以 `unknown tool ""` 到达运行时。该问题之所以漏过，是因为流式测试覆盖了字段缺失，却没有覆盖空占位符。适配器现仅接受非空的身份更新，并以回归测试复现该网关的分片形式。

## 概述

桌面应用中每次工具调用都显示 `Error: unknown tool ""`。模型给出了看似合理的参数，例如 `pwd && ls -la`，但实际执行记录中的工具名称为空，且没有可用 schema（模式）。

这不是工具未注册、沙箱拒绝或工具参数格式错误。会话事件日志显示，首个 `tool-call-delta` 已包含正确的 `callId` 和 `name: "bash"`；后续流式帧承载参数，却把重复的身份字段表示为 `""`。适配器在输出完整调用前，用这些空值覆盖了累积块中的身份。

## 影响

受影响模型无法通过该网关调用任何工具。它会重复尝试等价命令、消耗上下文，并在会话轨迹中留下难以理解的记录。在适配器修复且桌面应用重启前，用户无法依靠编码 Agent（智能体）执行检查、编辑或命令。

## 时间线

- 为 DeepSeek 模型配置了一个兼容 OpenAI Chat Completions 的自定义提供方。
- 首次工具请求在开头的流式 delta（增量）中生成了有效的 `bash` 身份，随后参数分片把 `id` 和 `function.name` 发送为空字符串。
- 完整工具调用事件包含 `id: ""` 和 `name: ""`；运行时返回 `Error: unknown tool ""`。
- 对会话日志的检查区分了模型最初的有效工具身份与适配器随后发生的覆盖。
- 适配器改为在后续分片提供空占位符时保留既有身份。目标翻译器测试使用该分片形式通过；随后重新构建 host 库并重启桌面应用。

## 根因

兼容 OpenAI 的流式 API（应用程序接口）对重复字段的表达并不统一。适配器原本能在后续 delta 省略 `id` 或 `function.name` 时保留先前值，但更新条件只检查 `!== undefined`。这个网关会在仅含参数的帧中使用 `""`，而不是省略字段，因此适配器把占位符误判为新的身份。

完整工具调用通过增量方式组装。保留的 `callId` 和工具名称一旦被替换为空字符串，运行时就无法解析任何已注册工具。参数 JSON（JavaScript Object Notation）仍然有效，使表面现象更像工具运行时问题，而不是流式翻译问题。

## 为什么防护措施未拦住

既有翻译器覆盖了后续身份字段缺失的分片，却没有模拟兼容网关发送空字符串占位符的行为。手动诊断最初聚焦于工具是否可用，因为最终错误是未知工具；决定性证据其实位于更早的流式事件序列中。

## 已添加的防护措施

- `packages/llm/llm-deepseek/src/translate.ts` 现在只在传入值非空时更新工具调用的 `callId` 和 `name`。首个分片没有身份仍属无效；本次变更只防止后续占位符抹除已知身份。
- `packages/llm/llm-deepseek/tests/translate.spec.ts` 复现了先发送 `call_bash` / `bash`，再发送空字符串身份占位符的情况，并断言每个输出 delta 和最终块都保留原始身份。
- 对 `unknown tool ""` 的排查从流式工具调用 delta 开始，以区分工具定义缺失与翻译阶段引入的空身份。

## 提供方侧修复

网关在序列化仅含参数的 `tool_calls` delta 时，必须省略 `id` 和 `function.name`，而不是输出 `""`。如果重复输出这些字段，其值必须与同一 `tool_calls[index]` 的首个分片完全一致。

正确的分片形式是先发送身份，再只发送参数：

```json
{"tool_calls":[{"index":0,"id":"call_xxx","type":"function","function":{"name":"bash","arguments":""}}]}
{"tool_calls":[{"index":0,"function":{"arguments":"{\\"command\\":\\"pwd\\"}"}}]}
```

第二行不得改为包含 `"id":""` 或 `"function":{"name":""}`。提供方应为 delta 中未出现的字段使用 `omitempty`、`undefined` 等可选字段序列化方式，并增加 SSE 回归测试：合并输出帧后，最终工具身份应仍为 `call_xxx` / `bash`。

## 教训

- 对流式协议而言，字段缺失与空字段具有不同的兼容性语义。状态累积应保留已确定的标识符，除非收到明确的非空替换值。
- 应定位第一个畸形事件，而不只看最终运行时错误。最终工具参数可以语法正确，但其身份可能已在更早处损坏。
- 兼容性测试应同时覆盖字段缺失和空占位符，因为不同网关可能以不同方式序列化部分 delta。
